Relational Model, SQL, PL/SQL & Integrity

Overview

This unit covers the relational model (data as tables), the formal query languages (relational algebra and calculus), and the practical language SQL along with PL/SQL and integrity constraints. It is the most practical unit and directly supports the DBMS Lab (MCA 205).

Detailed notes

1. Domains, relations and keys

A domain is the set of permitted values of an attribute. A relation is a table with tuples (rows) and attributes (columns); degree = number of columns, cardinality = number of rows. Kinds of relations: base (named) relations, views (virtual), snapshots and query results. Keys: candidate, primary, alternate (candidate keys not chosen as primary) and foreign.

2. Features of a good relational design and Codd’s rules

Good design avoids redundancy and update anomalies, preserves information and dependencies. Codd’s 12 rules (rule 0 + 12) define a true RDBMS, e.g. information rule (all data in tables), guaranteed access (table + key + column), systematic treatment of nulls, active online catalog, comprehensive data sub-language, view updating, high-level insert/update/delete, physical and logical data independence, integrity independence, distribution independence and the non-subversion rule.

Extended operations: generalized projection, aggregate functions (sum, avg, min, max, count), outer joins. Modification of the database: insertion, deletion and updating of tuples. Relational calculus is declarative: tuple relational calculus {t | P(t)} and domain relational calculus.

4. SQL: basic structure

SELECT [DISTINCT] columns FROM tables
[WHERE condition] [GROUP BY cols] [HAVING cond] [ORDER BY cols [DESC]];
  • Set operations: UNION, INTERSECT, EXCEPT/MINUS (UNION removes duplicates; UNION ALL keeps them).
  • Aggregates: COUNT, SUM, AVG, MIN, MAX. They ignore NULLs (except COUNT(*)).
  • Null values: any comparison with NULL is unknown; use IS NULL / IS NOT NULL.
  • Nested sub-queries: IN, NOT IN, EXISTS, ANY, ALL.
  • Derived relations: a sub-query in the FROM clause, with an alias.
  • Joins: INNER, LEFT/RIGHT/FULL OUTER, NATURAL, CROSS.

5. Views and DDL

A view is a virtual table defined by a query: CREATE VIEW v AS SELECT .... It gives security and simplicity. DDL commands: CREATE TABLE, ALTER TABLE (ADD/MODIFY/DROP column), DROP TABLE, TRUNCATE.

6. PL/SQL

PL/SQL is Oracle’s procedural extension of SQL with blocks: DECLARE … BEGIN … EXCEPTION … END;

  • Stored procedure/function – named block stored in the database and reused.
  • Trigger – code that fires automatically on INSERT/UPDATE/DELETE (BEFORE/AFTER, row/statement level).
  • Cursor – pointer to the result set of a query to process rows one by one. Implicit (created by Oracle) and explicit (OPEN, FETCH, CLOSE).

7. Database integrity

Integrity rules keep data correct: domain constraints (datatype, CHECK), attribute constraints (NOT NULL, DEFAULT), relation/entity integrity (primary key unique and not null), referential integrity (every foreign key value matches a primary key or is null) and database-level rules. An assertion is a condition the whole database must always satisfy: CREATE ASSERTION name CHECK (condition). In SQL, integrity is declared with PRIMARY KEY, UNIQUE, FOREIGN KEY ... ON DELETE CASCADE, CHECK and NOT NULL.

Diagrams & examples

-- Tables: Salesmen(snum, sname, city, commission), Customers(cnum, cname, city, rating, snum)
SELECT city, COUNT(*) AS total
FROM Customers
GROUP BY city
HAVING COUNT(*) > 1
ORDER BY total DESC;

-- Sub-query: customers served by salesmen of London
SELECT cname FROM Customers
WHERE snum IN (SELECT snum FROM Salesmen WHERE city = 'London');

-- Join
SELECT c.cname, s.sname FROM Customers c JOIN Salesmen s ON c.snum = s.snum;
-- Trigger: log deleted customers
CREATE OR REPLACE TRIGGER trg_cust_del
AFTER DELETE ON Customers
FOR EACH ROW
BEGIN
  INSERT INTO cust_log VALUES (:OLD.cnum, SYSDATE);
END;
/

-- Explicit cursor
DECLARE
  CURSOR c1 IS SELECT cname FROM Customers;
  v_name Customers.cname%TYPE;
BEGIN
  OPEN c1;
  LOOP
    FETCH c1 INTO v_name;
    EXIT WHEN c1%NOTFOUND;
    DBMS_OUTPUT.PUT_LINE(v_name);
  END LOOP;
  CLOSE c1;
END;
/

Relational algebra example: πcname(σrating>100(Customers)) – names of customers whose rating exceeds 100.

Important questions

Q1. Explain the basic relational algebra operations.

Select, project, union, difference, Cartesian product and rename are fundamental; intersection, join and division are derived. Give one example of each.

Q2. Differentiate WHERE and HAVING.

WHERE filters rows before grouping and cannot use aggregates; HAVING filters groups after GROUP BY and can use aggregate functions.

Q3. What is a view? State its advantages.

A virtual table defined by a stored query. It simplifies complex queries, restricts access to columns/rows (security) and supports logical data independence.

Q4. What are triggers and cursors in PL/SQL?

A trigger is code fired automatically by a DML event; a cursor is a handle on a query result set used to process rows one at a time (implicit/explicit).

Q5. Explain referential integrity with an example.

A foreign key value must exist as a primary key in the parent table (or be NULL), e.g. Customers.snum must exist in Salesmen.snum; ON DELETE CASCADE removes dependent rows.

Q6. State any five of Codd’s rules.

Information rule, guaranteed access, systematic treatment of nulls, physical data independence, view-updating rule.

Quick revision

  • Relation: degree = columns, cardinality = rows.
  • Algebra: σ rows, π columns, ⋈ join, ÷ “for all”.
  • SQL order: SELECT, FROM, WHERE, GROUP BY, HAVING, ORDER BY.
  • NULL: use IS NULL, aggregates skip NULLs.
  • PL/SQL: procedure, function, trigger, cursor.
  • Integrity: domain, entity, referential; assertion = global rule.
