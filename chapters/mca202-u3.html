Data Modeling

Overview

This unit covers models used to learn from data (Bayesian, SVM, neuro-fuzzy, PCA) and data models for big data stores (NoSQL, MongoDB, HBase). It links machine-learning ideas with the storage systems used for big data.

Detailed notes

1. Bayesian modeling

Based on Bayes’ theorem: P(θ|D) = P(D|θ)·P(θ) / P(D), i.e. posterior ∝ likelihood × prior. Beliefs (prior) are updated with data to give a posterior. Used in spam filtering, medical diagnosis, Bayesian networks and Naive Bayes classifiers. It naturally expresses uncertainty.

2. Support vector machines and kernel methods

An SVM finds the hyperplane that separates two classes with the maximum margin; the closest points to it are support vectors. A soft margin (parameter C) allows some misclassification. For non-linearly separable data, the kernel trick implicitly maps data to a higher-dimensional space: linear, polynomial, RBF (Gaussian) and sigmoid kernels.

3. Neuro-fuzzy modeling

Combines neural networks (learning ability) with fuzzy logic (human-like reasoning with IF–THEN rules and partial truth values between 0 and 1). The best-known system is ANFIS (Adaptive Neuro-Fuzzy Inference System), where a network tunes fuzzy membership functions and rules from data. Used in control systems and forecasting.

4. Principal component analysis (PCA)

A dimensionality-reduction technique that converts correlated variables into fewer uncorrelated principal components that capture maximum variance.

  1. Standardise the data.
  2. Compute the covariance (or correlation) matrix.
  3. Find eigenvalues and eigenvectors.
  4. Sort components by eigenvalue (variance explained).
  5. Keep the top k and project the data onto them.

5. Introduction to NoSQL and the CAP theorem

NoSQL databases are non-relational, schema-flexible and scale horizontally. Types: key-value (Redis), document (MongoDB), column-family (HBase, Cassandra) and graph (Neo4j). CAP theorem: a distributed system can guarantee only two of Consistency, Availability and Partition tolerance. Hence CP systems (HBase, MongoDB) and AP systems (Cassandra). NoSQL often follows BASE (Basically Available, Soft state, Eventual consistency) instead of ACID.

7. MongoDB database model, data types and sharding

Data is stored as BSON (binary JSON) documents inside collections. Data types: String, Integer, Double, Boolean, Array, Object (embedded document), Date, Null, ObjectId, Binary data, Timestamp, Regular expression. Sharding splits a collection across multiple servers using a shard key. Components: shards (hold data), mongos (query router) and config servers (metadata). It gives horizontal scalability; replica sets give availability.

8. Data modeling in HBase: defining schema

HBase is a column-oriented store on HDFS. A table has row keys (sorted), column families (declared in the schema) with column qualifiers created on the fly, and every cell is versioned by timestamp. Design the row key carefully for the access pattern and to avoid hot-spotting; keep few column families.

9. CRUD operations

Create, Read, Update, Delete – the four basic operations, shown in the examples for MongoDB and HBase.

Diagrams & examples

// MongoDB CRUD
db.students.insertOne({ roll: 1, name: "Asha", marks: [78, 85] })   // Create
db.students.find({ name: "Asha" })                                  // Read
db.students.updateOne({ roll: 1 }, { $set: { name: "Asha K" } })    // Update
db.students.deleteOne({ roll: 1 })                                  // Delete
sh.shardCollection("college.students", { roll: "hashed" })          // Sharding
# HBase shell CRUD
create 'student', 'info', 'marks'                 # schema: 2 column families
put 'student', 'r1', 'info:name', 'Asha'          # Create / Update
get 'student', 'r1'                               # Read
scan 'student'
delete 'student', 'r1', 'info:name'               # Delete
disable 'student'; drop 'student'

Important questions

Q1. State Bayes’ theorem and explain Bayesian modeling.

P(θ|D) = P(D|θ)P(θ)/P(D); the prior is updated by the likelihood to get the posterior.

Q2. What is the kernel trick in SVM?

Computing inner products in a high-dimensional feature space through a kernel function so non-linear boundaries become linear there.

Q3. Explain the CAP theorem.

A distributed store can provide only two of consistency, availability and partition tolerance.

Q4. Compare RDBMS and MongoDB.

Table/collection, row/document, fixed vs dynamic schema, joins vs embedding, vertical vs horizontal scaling.

Q5. Explain the steps of PCA.

Standardise, covariance matrix, eigen decomposition, choose top components, project.

Q6. Explain HBase data model.

Row key, column families, qualifiers, timestamped versions.

Quick revision

  • Posterior ∝ likelihood × prior.
  • SVM: max margin, support vectors, kernels.
  • Neuro-fuzzy = NN + fuzzy logic (ANFIS).
  • PCA: eigenvectors of covariance; keep top-k.
  • NoSQL types: key-value, document, column, graph; CAP: pick two.
  • MongoDB: BSON, _id, shard key, mongos. HBase: row key + column families + timestamp.
