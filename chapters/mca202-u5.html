Stream Analytics

Syllabus topics

Overview

In a data stream, data arrives continuously and rapidly and cannot be stored in full, so each item can be processed only once or a few times. This unit teaches the stream model and the classic approximate algorithms: sampling, Bloom filtering, Flajolet–Martin counting, moment estimation, DGIM and decaying windows.

Detailed notes

1. Introduction to stream concepts

A stream is an unbounded, ordered sequence of elements (sensor readings, clicks, stock ticks, tweets, network packets). Features: continuous arrival, high speed, limited memory, one-pass processing, and answers often approximate. Queries can be standing (continuous) or ad hoc.

2. Stream data model and architecture

Streams enter a Data Stream Management System (DSMS) through stream processors. The DSMS holds a small working store (memory) for summaries/sliding windows and an archival store (disk) not suited to fast queries. Standing queries run on the streams and write results to an output stream. DSMS vs DBMS: the DBMS stores persistent data and answers one-time queries; the DSMS processes transient data with continuous queries.

3. Stream computing

Processing data in motion with low latency, e.g. Apache Storm, Spark Streaming, Flink, Kafka Streams. Windows: sliding, tumbling; time-based or count-based.

4. Sampling data in a stream

To keep a representative sample, e.g. 1/10 of users’ queries, sample by key, not by tuple: hash the user id into 10 buckets and keep tuples hashed to bucket 0, so each sampled user has all their data. For a fixed-size sample of s elements use reservoir sampling: keep the first s; the n-th element replaces a random sample member with probability s/n.

5. Filtering streams

Selecting elements with a property, e.g. membership in a large set (valid email list). A Bloom filter uses an m-bit array and k hash functions: to add an item set k bits; to test, check that all k bits are 1. It has no false negatives but possible false positives, approx. (1 − e−kn/m)k. Optimal k = (m/n)·ln 2.

6. Counting distinct elements

Flajolet–Martin (FM): hash each element to a bit string, record the number of trailing zeros; let R be the maximum seen. Estimate distinct count ≈ 2R. Combine many hash functions (take averages within groups and the median of groups) to reduce error.

7. Estimating moments

For element frequencies mi, the k-th moment = Σ mik. 0th moment = number of distinct elements, 1st = stream length, 2nd = surprise number (unevenness of distribution). AMS algorithm: pick random positions, count occurrences of that element from that position onward (c); the estimate for the second moment is n(2c − 1), averaged over many variables.

8. Counting ones in a window: DGIM

To count 1s in the last N bits using only O(log²N) bits, DGIM divides the window into buckets whose sizes (number of 1s) are powers of two, with the timestamp of the most recent 1 in each. Rules: bucket sizes do not decrease going back in time; at most two buckets of each size; on a third, merge the two oldest. Estimate = sum of all buckets except half of the oldest. Error is at most 50% (improvable with more buckets per size).

9. Decaying window

Gives recent elements more weight. Each element is weighted (1 − c)i where i is its age and c is a small constant (e.g. 10−6). Update on a new element at+1: S ← S·(1 − c) + at+1. Useful for finding “currently popular/trending” items.

Second moment: stream a,b,c,b,d,a,c,d,a,b,d,c,a,a,b has counts a=5, b=4, c=3, d=3 ⇒ 2nd moment = 25+16+9+9 = 59.

# Python: decaying window and reservoir sampling
import random
def decay(S, x, c=1e-6): return S*(1-c) + x
def reservoir(stream, s):
    R = []
    for i, x in enumerate(stream, 1):
        if i <= s: R.append(x)
        elif random.random() < s/i: R[random.randrange(s)] = x
    return R

Important questions

Q1. What is a data stream? Explain stream architecture.

Unbounded rapid sequence of data; DSMS with stream processor, working store, archival store and standing queries.

Q2. Explain the Bloom filter. Can it give false negatives?

Bit array with k hashes for membership; false positives are possible but there are no false negatives.

Q3. Explain the Flajolet–Martin algorithm.

Hash elements, track the maximum number of trailing zeros R, estimate 2R distinct elements.

Q4. What is the second moment of a stream? Compute for counts 5,4,3,3.

The surprise number Σ mi² = 59.

Q5. Explain DGIM and decaying window.

DGIM counts 1s in a window with power-of-two buckets; decaying window exponentially down-weights older items.

Quick revision

  • Stream: one pass, limited memory, approximate answers.
  • Sample by key (hash users), reservoir for fixed size.
  • Bloom filter: no false negatives.
  • FM: 2R (R = max trailing zeros).
  • Moments: 0th distinct, 1st length, 2nd surprise number (AMS).
  • DGIM: buckets in powers of 2, ≤ 2 per size, error ≤ 50%.
  • Decaying window: S×(1−c) + new.
