MCA 201 · Unit III

Functional Dependencies & Normalization

Syllabus topics

Overview

Normalization is the process of organising tables to remove redundancy and the insertion, deletion and update anomalies it causes. This unit teaches functional dependencies (FDs) as the tool, and the normal forms (1NF to 5NF, BCNF) as the goal. Attribute-closure and normal-form numericals are very common in exams.

Detailed notes

1. Functional dependency (FD)

X → Y means: if two tuples agree on X they must agree on Y (X determines Y). Example: roll_no → name. X is the determinant, Y the dependent.

  • Trivial FD: Y ⊆ X (e.g. {roll_no, name} → name). Non-trivial: Y ⊈ X.
  • Armstrong’s axioms: Reflexivity (Y ⊆ X ⇒ X→Y), Augmentation (X→Y ⇒ XZ→YZ), Transitivity (X→Y, Y→Z ⇒ X→Z). Derived: union, decomposition, pseudo-transitivity.

2. Closure of FDs and of attributes

F+ (closure of a set of FDs) is the set of all FDs implied by F. X+ (closure of attributes) is the set of all attributes determined by X. If X+ contains all attributes of R, X is a super key; if minimal, a candidate key.

3. Irreducible (canonical/minimal) cover

  1. Make right sides single attributes.
  2. Remove extraneous attributes from left sides.
  3. Remove redundant FDs (those implied by the rest).

4. Normalization, decomposition and FD diagram

Normalization decomposes a relation into smaller ones. A good decomposition is lossless (non-loss) – the natural join of the parts gives back the original with no spurious tuples – and dependency preserving. Test for a binary split R into R1, R2: lossless if (R1 ∩ R2) → R1 or (R1 ∩ R2) → R2. An FD diagram draws attributes as nodes with arrows for FDs, making partial and transitive dependencies visible.

5. Normal forms

FormRule
1NFAll attribute values are atomic; no repeating groups.
2NF1NF + no partial dependency (no non-key attribute depends on part of a composite key).
3NF2NF + no transitive dependency. For every FD X→A: X is a super key, or A is a prime attribute.
BCNFFor every non-trivial FD X→Y, X must be a super key.
4NFBCNF + no non-trivial multivalued dependency (X →→ Y) unless X is a super key.
5NF (PJNF)No non-trivial join dependency unless implied by candidate keys.

3NF vs BCNF: 3NF can always be achieved with lossless and dependency-preserving decomposition; BCNF is lossless but may lose some dependencies.

6. Multivalued and join dependency

A MVD X →→ Y arises when one X value is associated with a set of Y values independent of the other attributes (e.g. Employee →→ Skill and Employee →→ Language in one table). 4NF splits them into (Employee, Skill) and (Employee, Language). A join dependency says the relation equals the join of several projections; 5NF removes it.

Diagrams & examples

Worked example: attribute closure and key

R(A, B, C, D, E)   F = { A -> B,  BC -> D,  D -> E }

(AC)+ : start {A, C}
        A -> B     => {A, B, C}
        BC -> D    => {A, B, C, D}
        D -> E     => {A, B, C, D, E}  = all attributes
So AC is a super key; A+ = {A,B} and C+ = {C} are not, hence AC is a candidate key.

Normalizing an order table

ORDER(order_id, item_id, item_name, qty, cust_id, cust_city)
Key = (order_id, item_id)
FDs: item_id -> item_name            (partial)   cust_id -> cust_city  (transitive)
     order_id -> cust_id

2NF/3NF result:
ITEM(item_id, item_name)
CUSTOMER(cust_id, cust_city)
ORDERS(order_id, cust_id)
ORDER_ITEM(order_id, item_id, qty)
Memory aid: 2NF removes partial dependencies; 3NF removes transitive ones; BCNF: “every determinant is a key”.

Important questions

Q1. What is a functional dependency? Explain trivial and non-trivial FDs.

X→Y holds if each X value determines exactly one Y value. Trivial if Y is a subset of X; otherwise non-trivial.

Q2. Explain 1NF, 2NF and 3NF with examples.

1NF: atomic values; 2NF: no partial dependency on a composite key; 3NF: no transitive dependency. Use the order-table example above.

Q3. Differentiate between 3NF and BCNF.

BCNF demands every determinant be a super key; 3NF also allows determinants whose dependents are prime attributes. BCNF may not preserve dependencies.

Q4. What is lossless decomposition?

A decomposition whose natural join reproduces the original relation exactly; checked by (R1∩R2)→R1 or R2.

Q5. Find the candidate key of R(A,B,C,D) with F = {A→B, B→C, C→D}.

A+ = {A,B,C,D}, so A is the only candidate key.

Q6. Explain 4NF and 5NF.

4NF removes non-trivial multivalued dependencies; 5NF removes join dependencies not implied by candidate keys.

Quick revision

  • X+ = all attributes ⇒ X is a super key.
  • Minimal cover: single RHS, no extraneous LHS, no redundant FD.
  • 1NF atomic → 2NF no partial → 3NF no transitive → BCNF determinant = key.
  • 4NF: MVD; 5NF: join dependency.
  • Always aim for lossless + dependency-preserving.
