MCA 201 · Unit VII

Data Warehouse & OLAP Technology for Data Mining

Syllabus topics

Differences between operational database systems and data warehousesA multidimensional data modelData warehouse architectureData warehouse implementationData cube technology

Overview

A data warehouse collects data from many operational systems into one place for analysis and decision making, and OLAP (Online Analytical Processing) lets analysts view that data from many dimensions. This unit explains the multidimensional model, architecture, implementation and the data cube.

Detailed notes

1. Operational database (OLTP) vs data warehouse (OLAP)

FeatureOperational DB (OLTP)Data warehouse (OLAP)
PurposeDay-to-day transactionsAnalysis and decision support
DataCurrent, detailedHistorical, summarised, integrated
OrientationApplication/processSubject (sales, customer)
OperationsShort read/write transactionsComplex read-mostly queries
UsersClerks, DBAsManagers, analysts
SizeMBs–GBsGBs–TBs
DesignER, normalisedStar/snowflake, denormalised

Characteristics of a warehouse: subject-oriented, integrated, time-variant, non-volatile.

2. Multidimensional data model

Data is viewed as a data cube with dimensions (descriptive perspectives: time, product, location) and facts/measures (numeric values: sales amount, units sold). Schemas:

  • Star schema: one central fact table linked to denormalised dimension tables.
  • Snowflake schema: dimension tables normalised into sub-tables; saves space, needs more joins.
  • Fact constellation (galaxy): several fact tables sharing dimension tables.

Each dimension has a concept hierarchy (e.g. day → month → quarter → year; street → city → state → country).

3. OLAP operations

  • Roll-up (drill-up) – climb a hierarchy or reduce dimensions (city → country).
  • Drill-down – opposite; more detail (year → quarter).
  • Slice – select on one dimension, giving a sub-cube. Dice – select on two or more dimensions.
  • Pivot (rotate) – reorient the cube axes.

4. Data warehouse architecture

Three tiers: bottom tier – warehouse database server fed from operational DBs and external sources through ETL (Extract, Transform, Load) with a metadata repository and data marts; middle tier – OLAP server; top tier – front-end tools (query, reports, analysis, data mining). Models: enterprise warehouse, data mart (department subset) and virtual warehouse (views over operational DBs).

5. OLAP server types

ROLAP (relational, scalable), MOLAP (array-based, fast but limited size) and HOLAP (hybrid).

6. Data warehouse implementation

Efficient implementation needs: materialisation of selected cuboids (choose which views to precompute), indexing (bitmap index, join index) for fast access, efficient processing of OLAP queries, and warehouse maintenance (refresh) plus metadata management.

7. Data cube technology

For n dimensions a data cube is a lattice of 2n cuboids (with hierarchies, even more). The base cuboid holds the lowest level of detail; the apex cuboid holds the grand total. The SQL operator CUBE (and GROUP BY ROLLUP) computes all group-bys. Because full materialisation is costly, partial materialisation and efficient computation methods (multiway array aggregation, iceberg cubes) are used.

Diagrams & examples

-- Star schema
SALES_FACT(time_key, item_key, branch_key, location_key, units_sold, dollars_sold)
TIME_DIM(time_key, day, month, quarter, year)
ITEM_DIM(item_key, item_name, brand, type)
LOCATION_DIM(location_key, street, city, state, country)

-- Roll-up using SQL
SELECT l.country, t.year, SUM(f.dollars_sold)
FROM sales_fact f
JOIN location_dim l ON f.location_key = l.location_key
JOIN time_dim t     ON f.time_key = t.time_key
GROUP BY CUBE (l.country, t.year);

Cuboids for dimensions (time, item, location): 23 = 8 – (time,item,location), (time,item), (time,location), (item,location), (time), (item), (location), and the apex ().

Important questions

Q1. Differentiate operational databases and data warehouses.

See the table: OLTP is current, detailed and transactional; the warehouse is historical, integrated and for analysis.

Q2. Explain star and snowflake schemas.

Star has one fact table with denormalised dimensions; snowflake normalises the dimensions into sub-tables.

Q3. Explain OLAP operations with examples.

Roll-up, drill-down, slice, dice and pivot on a sales cube.

Q4. Describe the three-tier data warehouse architecture.

Warehouse server with ETL, OLAP server (ROLAP/MOLAP/HOLAP), and front-end tools.

Q5. What is a data cube? How many cuboids exist for n dimensions?

A multidimensional view of facts by dimensions; 2n cuboids ignoring hierarchies.

Quick revision

  • Warehouse = subject-oriented, integrated, time-variant, non-volatile.
  • OLTP = transactions; OLAP = analysis.
  • Schemas: star, snowflake, fact constellation.
  • OLAP ops: roll-up, drill-down, slice, dice, pivot.
  • Architecture: ETL → warehouse → OLAP server → front-end.
  • n dimensions → 2n cuboids; base cuboid and apex cuboid.
