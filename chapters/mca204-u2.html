Overview

XML (eXtensible Markup Language) describes and carries data using tags you define yourself. This unit covers XML structure, how to check a document with a DTD, how to process it with parsers, and how to transform it into other formats with XSLT. Writing a DTD and an XSLT stylesheet are the most common exam tasks.

Detailed notes

1. Introduction to XML

XML is a W3C standard, text-based, self-descriptive language for storing and transporting data. Tags are not predefined: authors invent them (<student>, <marks>). It is platform- and software-independent, human and machine readable, and widely used in configuration files, data exchange, RSS feeds, web services (SOAP) and document formats.

2. Comparing XML with HTML

HTMLXML
Displays data and decides how it looksDescribes and carries data; decides what it is
Predefined tagsUser-defined tags
Not case-sensitiveCase-sensitive
Closing tags may be omitted (<br>)Every tag must be closed
Attribute values may be unquotedAttribute values must be quoted
Browsers are forgiving of errorsParsers stop at the first error

3. Structure of XML

  • Declaration (prolog): <?xml version="1.0" encoding="UTF-8"?> – optional, must be first.
  • Elements: <name>content</name>; exactly one root element; properly nested; empty element <br/>.
  • Attributes: name–value pairs in the start tag: <book id="101">.
  • Comments: <!-- comment -->.
  • CDATA sections: <![CDATA[ raw text with < and & ]]> – not parsed.
  • Processing instructions: <?xml-stylesheet type="text/xsl" href="s.xsl"?>.

Naming rules: begin with a letter or underscore, no spaces, case-sensitive, don’t start with “xml”.

4. XML entity references

Five predefined entities represent reserved characters: &lt; (<), &gt; (>), &amp; (&), &quot; ("), &apos; ('). Character references such as &#169; give Unicode characters. Custom entities can be defined in a DTD: <!ENTITY cp "Copyright 2026">, used as &cp;.

5. Parsers

An XML parser reads a document, checks it and exposes its content to programs. Non-validating parsers check only well-formedness; validating parsers also check against a DTD/schema. Types: DOM (loads the whole tree into memory; random access, can modify; heavy for large files), SAX (event-driven, streaming, low memory, read-only, forward-only) and pull parsers (StAX). PHP offers DOMDocument, SimpleXML and XMLReader.

6. Document Type Definitions (DTD)

A DTD defines the legal building blocks and structure of a document. It can be internal (inside <!DOCTYPE root [ … ]>) or external (<!DOCTYPE root SYSTEM "file.dtd">). Declarations:

  • <!ELEMENT name (content)> – content models: (#PCDATA) text, EMPTY, ANY, sequence (a,b), choice (a|b), with occurrence indicators ? (0 or 1), * (0 or more), + (1 or more).
  • <!ATTLIST element attr type default> – types: CDATA, ID, IDREF, NMTOKEN, enumerated (a|b); defaults: #REQUIRED, #IMPLIED, #FIXED "v" or a literal default.
  • <!ENTITY name "value">.

Limits: not XML syntax itself, no data types, no namespaces – XML Schema (XSD) overcomes these.

7. Using XSLT with XML

XSLT (eXtensible Stylesheet Language Transformations) is an XML-based language that transforms an XML document into HTML, plain text or other XML. It uses XPath to select nodes and templates to produce output. A stylesheet starts with <xsl:stylesheet version="1.0" xmlns:xsl="http://www.w3.org/1999/XSL/Transform"> and is linked to the XML with <?xml-stylesheet>.

8. xsl:template, apply-templates, import, include

  • <xsl:template match="XPath"> – defines output for matching nodes (match="/" = root).
  • <xsl:apply-templates select="..."/> – processes child nodes by applying the matching templates.
  • <xsl:include href="a.xsl"/> – inserts another stylesheet at the same precedence.
  • <xsl:import href="b.xsl"/> – imports a stylesheet whose rules have lower precedence (can be overridden); must come first.

9. xsl:element, xsl:attribute, xsl:value-of

  • <xsl:element name="p">…</xsl:element> – creates an element dynamically.
  • <xsl:attribute name="href">…</xsl:attribute> – adds an attribute to the enclosing element.
  • <xsl:value-of select="title"/> – outputs the text value of the selected node. <xsl:for-each select="catalog/book"> loops over nodes.

10. Conditional statements

<xsl:if test="price &gt; 300">…</xsl:if> (no else part) and <xsl:choose> with <xsl:when test=""> and <xsl:otherwise> for if–else-if–else. Operators < and & must be written as entities in tests.

11. Sorting elements

<xsl:sort select="name" order="ascending|descending" data-type="text|number"/> placed inside xsl:for-each or xsl:apply-templates.

12. XSLT functions

XPath/XSLT functions: node-set – count(), position(), last(); string – concat(), contains(), starts-with(), substring(), string-length(), normalize-space(), translate(); number – sum(), round(), floor(), ceiling(); boolean – not(), true(); XSLT-specific – format-number(), current(), generate-id().

13. Well-formed and valid documents

Well-formed = obeys XML syntax: one root, all tags closed and properly nested, quoted attribute values, case-matched tags, escaped special characters, unique attribute names in an element. Valid = well-formed and conforms to a DTD or schema. Every valid document is well-formed, but not vice versa.

Diagrams & examples

books.xml with an internal DTD and a stylesheet link:

<?xml version="1.0" encoding="UTF-8"?>
<?xml-stylesheet type="text/xsl" href="books.xsl"?>
<!DOCTYPE library [
  <!ELEMENT library (book+)>
  <!ELEMENT book (title, author, price)>
  <!ATTLIST book id CDATA #REQUIRED>
  <!ELEMENT title (#PCDATA)>
  <!ELEMENT author (#PCDATA)>
  <!ELEMENT price (#PCDATA)>
]>
<library>
  <book id="1"><title>DBMS</title><author>Korth</author><price>450</price></book>
  <book id="2"><title>AI</title><author>Rich</author><price>320</price></book>
</library>

books.xsl – table with sorting and a conditional:

<?xml version="1.0" encoding="UTF-8"?>
<xsl:stylesheet version="1.0" xmlns:xsl="http://www.w3.org/1999/XSL/Transform">
<xsl:template match="/">
  <html><body>
    <h2>Library</h2>
    <table border="1">
      <tr><th>Title</th><th>Author</th><th>Price</th></tr>
      <xsl:for-each select="library/book">
        <xsl:sort select="price" data-type="number" order="descending"/>
        <tr>
          <td><xsl:value-of select="title"/></td>
          <td><xsl:value-of select="author"/></td>
          <td>
            <xsl:choose>
              <xsl:when test="price &gt; 400"><b><xsl:value-of select="price"/></b></xsl:when>
              <xsl:otherwise><xsl:value-of select="price"/></xsl:otherwise>
            </xsl:choose>
          </td>
        </tr>
      </xsl:for-each>
    </table>
    <p>Total books: <xsl:value-of select="count(library/book)"/></p>
  </body></html>
</xsl:template>
</xsl:stylesheet>

Important questions

Q1. Differentiate between XML and HTML.

XML describes data with user-defined, case-sensitive, strictly closed tags; HTML displays data with predefined, forgiving tags.

Q2. Explain the structure of an XML document with an example.

Prolog, single root, elements, attributes, comments and CDATA, as in books.xml above.

Q3. What is a DTD? Write a DTD for a student record.

A set of declarations defining legal elements and attributes via ELEMENT and ATTLIST; show an internal DTD.

Q4. Differentiate well-formed and valid XML documents.

Well-formed follows syntax rules; valid is also checked against a DTD/schema.

Q5. Explain XSLT with xsl:template, xsl:for-each, xsl:sort and xsl:if.

Templates match nodes, for-each loops, sort orders output, if/choose give conditions; show the stylesheet.

Q6. What are DOM and SAX parsers?

DOM builds an in-memory tree (random access), SAX streams events (low memory, forward-only).

Q7. Differentiate xsl:import and xsl:include.

Include merges at equal precedence; import has lower precedence and can be overridden.

Quick revision

  • XML: user-defined tags, case-sensitive, one root, all tags closed, attribute values quoted.
  • Entities: &lt; &gt; &amp; &quot; &apos;; CDATA is not parsed.
  • DOM = tree in memory; SAX = event-based.
  • DTD: ELEMENT, ATTLIST, ENTITY; ? * + occurrence.
  • XSLT: template, apply-templates, value-of, for-each, if, choose, sort.
  • Valid ⇒ well-formed (not the reverse).
