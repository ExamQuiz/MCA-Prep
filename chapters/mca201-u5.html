Overview

This unit is a survey of newer database ideas (object-oriented, multimedia, web, warehousing and mining), followed by the physical side of databases: storage media, RAID, file organisation, indexing with B and B+ trees, and the older network and hierarchical models.

Detailed notes

1. Object-oriented databases (OODB)

OODBs store data as objects combining state (attributes) and behaviour (methods), suited to CAD, multimedia and engineering data where relational tables are awkward.

  • Object structure: attributes + methods + messages; an object class groups objects with the same structure and behaviour.
  • Inheritance: a subclass inherits attributes and methods of its superclass; multiple inheritance inherits from more than one superclass (may cause name conflicts).
  • Object identity (OID): a unique, system-generated identifier independent of the attribute values; it never changes, and objects with equal values can still be different objects.

2. Data warehousing and data mining (overview)

A data warehouse is a subject-oriented, integrated, time-variant, non-volatile collection of data supporting management decisions (Inmon). Data mining is discovering interesting, previously unknown patterns from large data sets. Details appear in Units VI and VII.

3. Database on the WWW

Web pages are linked to databases through CGI, servlets, JSP/PHP, ASP and application servers, so that dynamic pages are generated from query results. Three-tier architecture: browser → web/application server → database server. XML is used to exchange data.

4. Multimedia databases

They store images, audio, video and text. Differences from conventional DBMS: very large objects (BLOBs), special data formats (JPEG, MPEG, MP3), similarity-based retrieval (find images similar to a sample using features such as colour or shape, rather than exact match), and the need for continuous media delivery at a guaranteed rate without jitter. Video servers store compressed video on many disks and stream it to many clients (video-on-demand), needing real-time scheduling and high bandwidth. Issues: storage and compression, indexing, QoS, synchronisation.

6. Magnetic disk performance and optimisation

Access time = seek time + rotational latency + transfer time. Performance is improved by block-size selection, disk-arm scheduling (elevator algorithm), file organisation, non-volatile write buffers and log disks.

7. RAID (Redundant Array of Independent Disks)

  • RAID 0 – striping, no redundancy (speed).
  • RAID 1 – mirroring (reliability).
  • RAID 3/4/5 – striping with parity; RAID 5 distributes parity across all disks.
  • RAID 6 – double parity, survives two disk failures.

8. File organisation

Records may be fixed-length or variable-length (slotted-page structure, byte-string). File organisations: heap (any free space), sequential (sorted by search key), hash (hash function gives block) and clustering (related tables stored together).

9. Indexing and ordered indices

An index speeds up searching on a search key. Primary (clustering) index: file is sorted on the index key; secondary (non-clustering) index: on a non-sorting attribute. Dense index has an entry for every key; sparse has entries for some blocks only. Multilevel indexing indexes the index.

10. B-tree and B+-tree

  • Both are balanced multiway search trees with all leaves at the same level; a node of order n has at most n children and at least ⌈n/2⌉.
  • B-tree: keys and record pointers appear in both internal and leaf nodes; no key is repeated.
  • B+-tree: all record pointers are only in leaf nodes, which are linked sequentially; internal nodes hold only keys for routing. Hence faster range queries and higher fan-out. Insertion splits an overflowing node; deletion merges or redistributes an underflowing one. B+-trees are the standard in DBMS.

11. Network and hierarchical models

  • Hierarchical: data in a tree of parent–child record types; each child has exactly one parent (1:N). Simple and fast but cannot model M:N directly; shown with a tree-structure diagram.
  • Network (DBTG/CODASYL): records linked as a graph through sets (owner–member, 1:N); a record can be a member of several sets, so M:N is possible through a link record. Shown with a data-structure diagram. Navigation is by following pointers (find, get, store, modify, erase).
  • Implementation: pointers, linked lists, rings and index structures.

Important questions

Q1. What is object identity? Explain inheritance in OODB.

OID is a unique, immutable object identifier; subclasses inherit attributes and methods of superclasses, with multiple inheritance from several parents.

Q2. How do multimedia databases differ from conventional ones?

Large objects, special formats, similarity-based retrieval and continuous-media delivery with real-time constraints.

Q3. Explain RAID levels.

RAID 0 striping, 1 mirroring, 5 striping with distributed parity, 6 double parity; they trade speed, cost and reliability.

Q4. Differentiate B-tree and B+-tree.

B+ stores all data pointers in linked leaves, internal nodes only guide search; better for range queries and higher fan-out.

Q5. Explain dense and sparse indexes.

Dense: one entry per search-key value; sparse: one entry per block, needs a sorted file.

Q6. Compare hierarchical, network and relational models.

See comparison table in the notes: structure, relationships, access style and data independence.

Quick revision

  • OODB: object = state + behaviour; OID; inheritance.
  • Multimedia: similarity search, continuous media, video servers.
  • Disk access time = seek + rotation + transfer.
  • RAID 0 stripe, 1 mirror, 5 parity.
  • B+-tree: data in linked leaves; balanced.
  • Hierarchical = tree (1:N); Network = graph via sets (DBTG).
