MCA 202 · Unit VI

Introduction to Big Data

Syllabus topics

Overview

This unit explains how big data arose, what makes data “big”, how organisations judge and promote its business value, the best practices to follow, and the architecture (HDFS, MapReduce, YARN) that makes big data processing possible.

Detailed notes

1. Evolution of big data

Data processing moved from mainframes and file systems to relational databases (1970s–80s), data warehouses and BI (1990s), then the web and social media explosion (2000s), when Google published GFS and MapReduce papers leading to Hadoop (2006). Today: cloud, IoT sensors, mobile and real-time analytics. Drivers: cheap storage, commodity clusters, internet-scale data.

2. Big data characteristics

VMeaning
VolumeTerabytes to petabytes and beyond
VelocitySpeed of data creation and required processing
VarietyStructured, semi-structured, unstructured
VeracityAccuracy, trustworthiness, noise
ValueBusiness benefit extracted

3. Best practices for big data analytics

  • Start with a clear business question and a pilot project.
  • Define data governance, quality, security and privacy policies.
  • Use the right tool: scale-out storage, in-memory and parallel processing.
  • Build a skilled, cross-functional team; involve business users.
  • Iterate, measure results and integrate with existing BI.

4. Validating

Before investing, the organisation must validate that big data fits the need: check whether the business problem really needs volume/variety/velocity, validate data quality, source and veracity, and test models on held-out data before acting on results. A small proof-of-concept validates the value claimed.

5. The promotion of the value of big data

To get management buy-in, link big data to business goals: increase revenue (personalised offers), reduce cost (predictive maintenance), manage risk (fraud detection) and improve customer satisfaction. Communicate success stories and measurable benefits.

6. Big data use cases

Retail recommendation and market-basket analysis, banking fraud detection, healthcare diagnostics, telecom churn prediction, smart grids and IoT, log and security analytics, social-media sentiment, transportation and route optimisation.

7. Characteristics of big data applications

Applications that benefit most have data-intensive processing, need for scalable parallelism, diverse data sources, tolerance for approximate results, analytics on historical and streaming data, and need for fast time-to-insight.

8. Perception and quantification of value

Value is judged by perception (executives’ belief) and must be quantified: increased revenue, cost savings, productivity, reduced risk; measured by ROI, total cost of ownership (hardware, software, people), time to value and customer metrics. Both tangible and intangible benefits are considered.

9. Understanding big data storage

Big data is stored on distributed, scale-out systems: distributed file systems (HDFS), NoSQL databases, object stores and cloud storage. Principles: horizontal scaling, replication for fault tolerance, data locality, and cheap commodity disks.

10. High-performance architecture overview

A cluster of commodity nodes in a shared-nothing design, with a master coordinating many workers, fast network, parallel processing and moving computation to data. Layers: storage, resource management, processing frameworks, analytics tools.

11. HDFS

Master/slave file system: NameNode stores metadata, DataNodes store 128 MB blocks replicated 3 times; write-once, read-many, streaming access, fault tolerant.

12. MapReduce and YARN

YARN (Yet Another Resource Negotiator, Hadoop 2) separates resource management from processing. ResourceManager allocates cluster resources; NodeManager on each node manages containers; a per-application ApplicationMaster negotiates resources and runs tasks. Besides MapReduce, YARN also runs Spark, Tez, etc., which improves utilisation and scalability over Hadoop 1’s JobTracker/TaskTracker.

13. MapReduce programming model

Input split → Map (key/value pairs) → optional Combiner → Partition → Shuffle & sort → Reduce → output to HDFS. The framework handles parallelism, scheduling, data movement and failures (re-running failed tasks); programmers write only map and reduce.

Important questions

Q1. Explain the characteristics of big data.

Volume, velocity, variety, veracity and value.

Q2. What are best practices for big data analytics?

Business-driven pilots, governance, right tools, skilled team, iteration and measurement.

Q3. How is the value of big data quantified?

Through ROI, cost savings, revenue growth, risk reduction, TCO and time to value.

Q4. Explain YARN architecture.

ResourceManager, NodeManagers with containers, and per-application ApplicationMaster.

Q5. Explain the MapReduce programming model.

Split, map, combine, partition, shuffle/sort, reduce, with framework handling parallelism and faults.

Quick revision

  • Big data: 5 Vs – volume, velocity, variety, veracity, value.
  • Hadoop grew out of Google GFS/MapReduce.
  • Best practice: business question, governance, pilot, team.
  • Value: ROI, cost, revenue, risk.
  • Shared-nothing scale-out cluster; computation moves to data.
  • YARN: RM, NM, AM, containers. MapReduce: map → shuffle → reduce.
