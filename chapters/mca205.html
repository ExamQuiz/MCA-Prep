🧪 DBMS Lab

Max / Min marks: 100 / 50Practical

SQL practicals on the Salesmen, Customers and Orders tables (45 queries), with solutions, outputs and viva questions.

Overview

This lab practises the SQL covered in MCA 201 (Unit II). All 45 queries use three related tables: Salesmen (SNUM, SNAME, CITY, COMMISSION), Customers (CNUM, CNAME, CITY, RATING, SNUM) and Orders (ONUM, AMOUNT, ODATE, CNUM, SNUM). Each question below has the SQL solution and the output produced by the sample data given in this page. The SQL is written to run on Oracle (the usual lab software) and also on MySQL; differences are noted.

How to use: (1) create the tables, (2) insert the sample data, (3) type each query yourself before looking at the answer, (4) compare your output with the one shown. Your own marks may use different data, so understand the logic rather than memorising the output.

1. Lab setup

  • Oracle: open SQL*Plus or SQL Developer, log in, paste the scripts below. Use SET LINESIZE 150 and SET PAGESIZE 50 for neat output.
  • MySQL: open MySQL Workbench or the command line, run CREATE DATABASE lab; USE lab; then the scripts.
  • No software? Use an online SQL editor such as SQLite/DB Fiddle for practice (some syntax like ANY/ALL is not supported in SQLite).

Create the tables

CREATE TABLE Salesmen (
  snum       INT PRIMARY KEY,
  sname      VARCHAR(20) NOT NULL,
  city       VARCHAR(20),
  commission DECIMAL(4,2)
);

CREATE TABLE Customers (
  cnum   INT PRIMARY KEY,
  cname  VARCHAR(20) NOT NULL,
  city   VARCHAR(20),
  rating INT,
  snum   INT,
  FOREIGN KEY (snum) REFERENCES Salesmen(snum)
);

CREATE TABLE Orders (
  onum   INT PRIMARY KEY,
  amount DECIMAL(10,2),
  odate  DATE,
  cnum   INT,
  snum   INT,
  FOREIGN KEY (cnum) REFERENCES Customers(cnum),
  FOREIGN KEY (snum) REFERENCES Salesmen(snum)
);

E. ANY, ALL and IN

Q34. Salesmen with customers located in their cities, using ANY and IN.

-- Using ANY
SELECT *
FROM Salesmen s
WHERE s.city = ANY (SELECT c.city FROM Customers c WHERE c.snum = s.snum);
-- Using IN
SELECT *
FROM Salesmen s
WHERE s.city IN (SELECT c.city FROM Customers c WHERE c.snum = s.snum);

Output (with the sample data)

SNUM  SNAME   CITY    COMMISSION
----  ------  ------  ----------
1001  Peel    London  0.12      
1002  Serres  Surat   0.13      
1005  Sejal   Surat   0.14      
1006  Piyush  Rome    0.09      
1007  Rafkin  Rome    0.15      
(5 rows)

= ANY is equivalent to IN. This is a correlated sub-query (it uses s.snum from the outer query).

Q35. Salesmen for whom there are customers that follow them in alphabetical order.

5. Quick SQL revision

  • Order of clauses: SELECT → FROM → WHERE → GROUP BY → HAVING → ORDER BY.
  • Patterns: LIKE 'C%', BETWEEN a AND b, IN (...), IS NULL.
  • Aggregates: COUNT, SUM, AVG, MIN, MAX (ignore NULLs); use GROUP BY for per-group results.
  • Joins: list tables with a join condition; self join uses two aliases of one table.
  • Sub-queries: IN, EXISTS, > ANY (greater than min), > ALL (greater than max).
  • Sets: UNION (no duplicates), UNION ALL (keeps duplicates), INTERSECT, MINUS/EXCEPT.
  • DML: INSERT, UPDATE ... SET ... WHERE, DELETE ... WHERE – always use WHERE and finish with COMMIT/ROLLBACK.

6. Viva questions

Q1. What is a DBMS? Name some popular ones.

Software that creates, stores, retrieves and controls access to a database. Examples: Oracle, MySQL, SQL Server, PostgreSQL, SQLite.

Q2. What is the difference between DDL, DML, DCL and TCL?

DDL defines structure (CREATE, ALTER, DROP, TRUNCATE); DML manipulates data (SELECT, INSERT, UPDATE, DELETE); DCL controls access (GRANT, REVOKE); TCL manages transactions (COMMIT, ROLLBACK, SAVEPOINT).

Q3. What is a primary key? How is it different from a unique key?

A primary key uniquely identifies each row, cannot be NULL and there is only one per table. A unique key also prevents duplicates but allows NULL (in most DBMS) and a table can have several.

Q4. What is a foreign key?

A column that refers to the primary key of another table, enforcing referential integrity (e.g. Customers.snum refers to Salesmen.snum).

Q5. Difference between WHERE and HAVING.

WHERE filters rows before grouping and cannot use aggregates; HAVING filters groups after GROUP BY and can use aggregates.

Q6. Difference between DELETE, TRUNCATE and DROP.

DELETE removes selected rows (can be rolled back, fires triggers); TRUNCATE removes all rows quickly (structure stays, usually cannot be rolled back); DROP removes the whole table.

Q7. What are the different types of joins?

INNER, LEFT OUTER, RIGHT OUTER, FULL OUTER, CROSS and SELF join (a table joined with itself, as in Q27).

Q8. What is the difference between UNION and UNION ALL?

UNION removes duplicate rows from the combined result; UNION ALL keeps all rows and is faster.

Q9. What is a sub-query? Correlated vs non-correlated?

A query inside another query. A non-correlated sub-query runs once; a correlated one refers to the outer query's columns and runs once per outer row (Q34).

Q10. What do ANY and ALL mean?

x > ANY(set) is true if x is greater than at least one value (the minimum); x > ALL(set) is true if x is greater than every value (the maximum).

Q11. How do you handle NULL values?

Use IS NULL / IS NOT NULL, and functions like NVL (Oracle), COALESCE or IFNULL. Comparisons with NULL give unknown, and aggregates ignore NULLs.

Q12. Difference between COUNT(*), COUNT(column) and COUNT(DISTINCT column).

COUNT(*) counts all rows; COUNT(column) counts non-NULL values; COUNT(DISTINCT column) counts different non-NULL values.

Q13. What is the use of GROUP BY?

It groups rows with the same value so aggregate functions (SUM, AVG, MAX, MIN, COUNT) are calculated for each group.

Q14. What is a view?

A virtual table based on a SELECT query; it stores no data of its own and is used for security and simplicity.

Q15. What are COMMIT and ROLLBACK?

COMMIT makes the changes of a transaction permanent; ROLLBACK undoes the changes since the last commit.

Q16. What is normalization?

Organising tables to remove redundancy and update anomalies (1NF, 2NF, 3NF, BCNF).

Q17. What does the LIKE operator do?

Pattern matching on text: % matches any number of characters, _ matches one character.

Q18. How does the DISTINCT keyword work?

It removes duplicate rows from the result set (Q5, Q15).

7. Tips for the practical record and exam

  • For each query write: aim / question, SQL statement, output (screenshot or pasted text).
  • Include the table structures (DESC) and the table data at the start of the record.
  • Test with SELECT before running DELETE or UPDATE; use ROLLBACK to undo mistakes.
  • If you get ORA-00904 invalid identifier check column names; ORA-00933 usually means a syntax error such as AS before a table alias.
  • Be ready to explain every clause in your query and to change a condition during the exam.
