MCA 203 · Unit IV

Natural Language Processing, Game Playing and Planning

Syllabus topics

Overview

This unit covers three application areas of AI: understanding natural language (grammars, parsers, semantics), game playing with minimax and alpha-beta pruning, and planning sequences of actions (goal-stack and non-linear planning, with the blocks world as the standard domain).

Detailed notes

1. Parsing techniques

Parsing analyses a sentence according to a grammar and produces a parse tree. Natural language processing (NLP) stages: morphological/lexical analysis, syntactic analysis (parsing), semantic analysis, discourse integration and pragmatic analysis. Techniques: top-down (start from S and expand rules to match the words), bottom-up (start from words and reduce to S), chart parsing (stores partial results to avoid recomputation) and deterministic/non-deterministic parsers. Problems: ambiguity (lexical, syntactic, semantic) and backtracking.

2. Context-free grammar (CFG)

Rewrite rules with a single non-terminal on the left: S → NP VP; NP → Det N; VP → V NP. Defined by terminals, non-terminals, start symbol and productions. Simple and efficient, but cannot easily handle agreement (number, gender), long-distance dependencies or meaning.

3. Recursive transition networks (RTN)

A grammar drawn as a network of states and arcs; arcs are labelled by word categories or by names of other networks, which can be called recursively (so RTN equals CFG in power). A sentence is accepted if a path reaches the final state.

4. Augmented transition networks (ATN)

An RTN extended with registers (store features such as number, tense, subject), tests on arcs (e.g. subject–verb agreement) and actions that set registers. ATNs can handle agreement and build deep-structure representations; more powerful than RTN.

5. Case and logic grammars

  • Case grammar (Fillmore): analyses a sentence as a verb with case roles – agent, object, instrument, location, source, goal, beneficiary – emphasising meaning over word order. “Ram opened the door with a key”: Agent = Ram, Object = door, Instrument = key.
  • Logic grammars: grammars written as logic clauses, e.g. Definite Clause Grammars (DCG) in Prolog, where the Prolog interpreter itself acts as a parser: sentence --> np, vp.

6. Semantic analysis

Assigns meaning to the parsed sentence: lexical semantics (word senses, disambiguation), compositional semantics (meaning of the whole from the parts), use of semantic grammars and case frames, and mapping to a knowledge representation such as logical forms or conceptual dependency. Semantic and syntactic analysis can be interleaved to prune ambiguous parses.

7. Game playing: minimax

For two-player, zero-sum, perfect-information games (chess, tic-tac-toe). The game tree alternates MAX (our move; picks the highest value) and MIN (opponent; picks the lowest) levels. Leaves get a static evaluation; values are backed up level by level. For tic-tac-toe a simple evaluation: (lines open for X) − (lines open for O). Limited by depth because the tree grows as bd.

8. Alpha-beta cutoffs and refinements

Alpha-beta pruning returns the same value as minimax but prunes branches that cannot influence the decision. α = best value found so far for MAX (lower bound); β = best value for MIN (upper bound). Prune when α ≥ β. In the best case, with good move ordering, the number of nodes searched is about O(bd/2), allowing the search to go twice as deep. Refinements: waiting for quiescence (don’t stop evaluating in unstable positions), secondary search, iterative deepening, move ordering, book moves, and alternatives like the killer heuristic.

9. Planning: overview and the blocks world

Planning = finding a sequence of operators that transforms the initial state into the goal state (unlike plain search, it uses structured actions and sub-goals). Blocks world: blocks on a table moved by a one-handed robot arm. Predicates: ON(A,B), ONTABLE(A), CLEAR(A), HOLDING(A), ARMEMPTY. Operators (each with precondition, add list, delete list): STACK(A,B), UNSTACK(A,B), PICKUP(A), PUTDOWN(A).

10. Components of a planning system

(1) Choose the best rule to apply (using differences between current and goal states); (2) apply the rule to compute the new state (the frame problem: what does not change); (3) detect a solution; (4) detect dead ends; (5) repair almost-correct solutions.

11. Goal stack planning

Maintain a stack of goals, operators and compound-goal lists plus the current state. Algorithm: pop the top; if it is a compound goal, push its sub-goals (and the compound goal itself, to re-check); if a single unsatisfied goal, push an operator that achieves it and then that operator’s preconditions; if an operator, apply it and update the state and plan; if an already true goal, discard. Weakness: it solves sub-goals in a fixed order and can produce inefficient plans or fail on interacting goals (Sussman anomaly).

12. Non-linear planning

Plans are partially ordered sets of actions rather than a strict sequence; ordering decisions are delayed until necessary (least commitment). Uses constraint posting: add ordering and variable-binding constraints, and detect/resolve threats (an action that undoes another’s effect) by reordering. Handles the Sussman anomaly; examples: NOAH, TWEAK.

Diagrams & examples

Alpha-beta example. MAX root, three MIN children with leaf values [3, 5], [2, 9], [0, 1]:

MIN-1 sees 3, 5  -> value 3 ;  MAX: α = 3
MIN-2 sees 2 (≤ α = 3) -> cutoff, leaf 9 is pruned ;  value ≤ 2
MIN-3 sees 0 (≤ α = 3) -> cutoff, leaf 1 is pruned
Root value = max(3, 2, 0) = 3   (same as minimax, fewer nodes examined)

Parse of “the boy eats an apple” with S → NP VP, NP → Det N, VP → V NP:

S
 +-- NP (Det the, N boy)
 +-- VP (V eats, NP (Det an, N apple))

Blocks world operator: STACK(A,B) – precondition: CLEAR(B) ∧ HOLDING(A); delete: CLEAR(B), HOLDING(A); add: ON(A,B), CLEAR(A), ARMEMPTY.

Important questions

Q1. Explain top-down and bottom-up parsing with an example.

Top-down expands S to match words; bottom-up reduces words to S; show a parse tree for a simple sentence.

Q2. Differentiate RTN and ATN.

ATN adds registers, tests and actions to RTN, handling agreement and building structures.

Q3. Explain the minimax procedure and alpha-beta pruning.

MAX/MIN backing up of values; pruning when α ≥ β gives the same result with far fewer nodes.

Q4. What is case grammar?

Verb-centred analysis with case roles like agent, object and instrument.

Q5. Explain the components of a planning system.

Choosing rules, applying them, detecting solutions and dead ends, and repairing near-solutions.

Q6. Explain goal stack planning in the blocks world. What is non-linear planning?

Goals and operators on a stack; non-linear planning uses partial order and constraint posting to avoid goal interaction.

Quick revision

  • NLP: lexical → syntactic → semantic → discourse → pragmatic.
  • CFG → RTN (networks) → ATN (+registers, tests, actions).
  • Case grammar: agent, object, instrument; DCG in Prolog.
  • Minimax: MAX high, MIN low; alpha-beta prunes when α ≥ β.
  • Blocks world: ON, ONTABLE, CLEAR, HOLDING, ARMEMPTY; STACK/UNSTACK/PICKUP/PUTDOWN.
  • Goal stack = fixed order; non-linear = partial order, constraint posting.
